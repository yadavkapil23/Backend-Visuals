The Controller

If the Router is the traffic cop, the Controller is the brains.
It receives the request, makes decisions, talks to the database, and decides what response to send back.

const loginController = async (req, res) => {
  const { email, pass } = req.body;

  // 1. Validation Layer
  if (!isValidEmail(email)) {
    return res.status(400).json({ error: "Bad Email" });
  }

  // 2. Processing Layer (Model)
  const user = await User.findOne({ email });
  if (!user || user.pass !== pass) {
    return res.status(401).json({ error: "Wrong Creds" });
  }

  // 3. Response Layer
  return res.status(200).json({ token: "abc-123" });
};
rule

1. Input Validation

The controller's first job is defense. Is the email valid? Is the password long enough? If not, it rejects the request immediately (Early Return).

handyman

2. Business Logic

This is the "work". The controller calls Models or Services to fetch data from the database, process payments, or calculate values.

output

3. Response Formatting

The controller decides how to reply. Should it render an HTML page? Or return a JSON object for an app? It sets the Status Code (200, 404, etc).

Pro Tip: Keep it Skinny!

A common design pattern is "Skinny Controller, Fat Model" (or Service). The Controller should just be a coordinator. It shouldn't contain complex algorithms or 100 lines of database queries. Delegate the heavy lifting to service files so your code stays clean and reusable.
